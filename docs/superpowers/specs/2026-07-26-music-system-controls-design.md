# 音乐系统媒体控件同步设计

## 目标

修复音乐播放过程中系统媒体控件与音乐面板状态不同步的问题：

- 锁屏界面、通知栏、蓝牙耳机/车机显示当前歌曲对应的专辑封面和歌曲信息。
- 后台播放切回音乐面板时，进度条显示真实播放进度，而不是 `0:00`。
- 切歌、暂停、继续、拖动进度和自动下一首后，各媒体控件保持一致。

## 现状与问题

音乐播放基于 Media3 `MediaSessionService` 和 `MediaController`。当前 `MediaItem` 只写入标题和歌手，未写入 `artworkUri` 或封面数据，因此系统媒体控件无法可靠获得当前专辑封面。

面板的 `duration` 与 `currentPosition` 主要由播放状态监听和面板定时刷新更新。面板关闭后再次打开时，控制器可能尚未进入 `STATE_READY`，状态对象仍保留初始值，导致进度显示为 `0:00`。

## 设计方案

### 媒体元数据

在构造 `MediaItem` 时写入完整媒体元数据。封面来源沿用面板显示优先级：

1. 有效的本地缓存封面；
2. 网易云封面 URL；
3. 本地嵌入专辑图；
4. 无封面时不设置图片，保留系统默认媒体图标。

本地缓存封面需要转换为系统可访问的稳定 URI，不能直接把应用私有文件路径作为系统媒体封面。网易云封面使用网络 URI。封面加载失败不得影响音频播放。

切换歌曲、恢复播放队列和控制器重新连接时，MediaSession 使用对应 `MediaItem` 的元数据，使系统媒体控件自动刷新歌曲、歌手和封面。

### 播放状态同步

在控制器建立连接、面板重新显示以及播放器进入 `STATE_READY` 时，从 `MediaController` 主动同步：

- 当前媒体项及对应的面板曲目；
- 总时长；
- 当前播放位置；
- 是否正在播放。

进度位置继续由面板显示期间的定时刷新更新；后台播放不依赖 Compose 面板生命周期。同步时仅使用控制器的有效值，避免控制器暂未准备完成时用 `0L` 覆盖已保存进度。

### 生命周期

音乐面板关闭时保留正在播放的控制器和播放状态。重新显示后先连接或复用控制器，再执行一次状态同步，随后恢复 UI 刷新。暂停状态仍按现有逻辑释放空闲资源，播放中的资源不释放。

## 涉及组件

- `MusicPlayerHelper.kt`：构造带封面的 `MediaItem`，在控制器连接和切歌后触发状态同步。
- `MusicPlaybackState.kt`：集中实现从 `MediaController` 同步歌曲、时长、位置和播放状态的方法，并修正 `STATE_READY` 时的状态更新时序。
- `MusicPlaybackService.kt`：保持 MediaSession 生命周期和 Media3 通知更新，避免额外实现重复的通知逻辑。
- `MusicPanelViewManager.kt`：面板显示初始化完成后触发一次播放状态同步。

## 错误处理

- 封面文件不存在、网络 URL 无效或加载失败时，继续播放并使用无封面状态。
- 控制器尚未连接或播放器尚未准备完成时，不覆盖已有的有效进度和时长。
- 曲目无法映射到当前播放列表时，仅更新可确定的播放状态，不修改当前曲目。

## 验收标准

1. 播放歌曲 A 后切换歌曲 B，锁屏、通知栏、蓝牙耳机/车机显示的歌曲信息和封面均切换到 B。
2. 播放过程中关闭并重新打开音乐面板，进度条和左侧时间不回到 `0:00`，且与实际播放位置基本一致。
3. 暂停、继续、拖动进度和自动切歌后，面板与系统媒体控件的播放状态一致。
4. 本地缓存封面、网易云封面、本地嵌入封面和无封面歌曲均能正常播放。
5. 封面读取或加载失败不会导致播放异常。

## 自检结论

- 未包含未决占位项或 TODO。
- 方案只覆盖系统媒体信息和播放状态同步，不改变扫描、播放列表排序和歌词功能。
- MediaSession、面板 UI 和共享状态的职责边界保持不变。
